# Rust 任务工作台

本轮参考本机 WorkBuddy 5.8.2 安装包的静态结构，独立实现 Agent Core 原生工作台。
应用构建、运行和测试仍只需要根 Cargo workspace，不包含 WorkBuddy JavaScript、品牌资源或运行时。

## 使用

- 左栏「任务中心」：按任务名称/工作区搜索，切换全部、已完成、待处理。
- 点击任务返回对话；恢复其他会话仍经过现有扩展生命周期和可取消工作线程。
- 「当前对话」保留未发送草稿；任务模板只填入草稿，不自动请求模型。
- 顶栏「任务详情」：查看产物、执行记录、概览。宽度至少 1200px 时使用右栏，否则用可关闭浮窗。
- 任务详情从当前分支的完整祖先链读取记录，保留压缩前唯一匹配的成功 `write`/`edit` 产物；显示路径、稳定记录 ID 及已有 diff，支持复制路径。
- 「查看当前文件」通过工作线程读取实际文件，显示 UTF-8 文本、字节数和 SHA-256；「刷新预览」重新读取，「取消预览」或「关闭预览」释放展示状态。预览是读取时的磁盘快照，不是历史版本或实时监听，也不执行文件。
- 当前文本预览上限为 256 KiB；不存在、目录、二进制/其他编码、超限、正在变化、访问失败分别显示结果。仅接受当前分支中已记录的成功文件操作，检查工作区边界、特殊路径、链接和重解析点。
- 切换分支或追加消息会更新详情缓存；「刷新记录」可重新校验历史。损坏的分支显示错误，不沿用另一分支的产物。
- 现有 DeepSeek、智谱、OpenAI API Key/Codex 登录、模型刷新、快速切换、深浅主题和权限设置保持原有入口。

任务中心状态依据当前上下文的最后一条有效消息；任务详情依据当前分支完整历史的最后一条有效消息：未开始、待继续、已完成、已停止、错误、输出上限。压缩摘要不作为详情中的用户输入或任务状态依据。
正在运行是临时显示状态，重启不会把旧会话伪装为仍在后台执行。
工具失败不等于整个任务最终失败，后续模型可能恢复；原始工具结果仍单独显示失败。
准备阶段错误/扩展处理结果继续显示在原有状态栏，不伪造已持久化的模型消息。

## 任务整理与归档

任务的置顶和归档是组织状态，不是模型执行结果。归档不删除会话、产物或持久队列，恢复归档不将失败任务标为完成。

- 首次置顶移到置顶列表最前；再次置顶不改变顺序。取消置顶回到普通任务列表。
- 置顶顺序独立保存，不随消息更新时间变化；上下移动保留被搜索条件或归档筛选隐藏的其他置顶任务。
- 归档保留原置顶位置。任务中心提供归档入口，侧栏不把归档任务继续列为普通任务。
- 归档不是停止按钮：正在执行的模型循环及其已排队输入继续执行，结果仍保存。归档阻止新的界面发送和空闲自动派发；需要中断时使用原有「停止」。显式恢复后沿用原队列的暂停与重启隔离状态，不自动清除它们。
- 任务状态使用会话目录中的 `task-catalog.state`，与消息内容分开，普通会话保存不会覆盖它。全局 revision、进程锁和原子发布将一次置顶重排作为完整事务；旧版本操作需要刷新后重新确认。
- 状态损坏或保存未确认时保留文件并显示错误，不将任务默认为未归档继续派发。任务整理操作在工作线程执行；取消发生在提交前才中止写入，已经提交的结果仍按真实状态显示。
- 其他实例的修改通过「刷新任务状态」读取；写入时的 revision 冲突会拒绝旧操作。当前没有跨窗口实时事件同步，进程锁也不代表跨窗口执行调度已实现。

这些行为参考 WorkBuddy 5.8.2 的本地 conversations facade 与有序置顶存储；原厂未读标记、分组和云端同步不由本节提供。具体静态证据与未知项见 `.artifacts/workbench-task-management-20261015/REFERENCE.md`。

## 可管理消息队列

- 顶栏「消息队列」显示当前会话待发送项，支持加入当前输入、同类消息上移/下移、移除、清空、暂停/恢复和优先发送。窗口内入队使用普通 follow-up；执行中的输入区发送仍保留 steering 行为。
- 桌面队列使用会话内稳定 ID；切换会话后保留各自的待发送队列。准备后的消息、原始输入、原始图片、排序及派发记录保存到会话文件旁的 `<session-id>.queue` 目录。仅排队、尚未执行过任务的新会话也可在重启后找到。
- 「移回编辑」把消息移出队列并恢复原始输入（如有）和图片附件，同时暂停其余消息；输入框已有草稿时不覆盖。重新发送再次经过正常输入处理，直接派发已准备消息不重复运行输入钩子。
- 「停止」取消当前执行并暂停剩余队列；「清空待发送」才删除待发送项。「立即发送」允许越过暂停，在下一个可接收消息的边界交给运行时，不中断正在执行的工具。
- 队列移出、派发次数和模型成功是不同状态。已写入会话的输入遇到模型失败仍保留在历史中，不自动重复发送；准备失败保留输入用于恢复。
- 空闲派发时如果输入验证失败，该项原始草稿及图片移回输入框供修正，不同时保留一份重复待发送项。执行失败后阻止自动派发剩余项，需显式恢复或优先发送。
- Runtime 保留 steering/follow-up 及 All/OneAtATime 模式；立即项优先。预算耗尽或取消时不提前消费队列，可执行待发送项触发原有轮数上限错误。
- 界面按会话和队列版本缓存快照，实际执行使用现有可取消 worker、共享 Rust loop 和 SessionStore，不增加模拟成功通道。

### 重启恢复与保存确认

- 重启恢复后，所有通道（包括立即发送）先隔离，不自动请求模型。检查原工作区和内容后点击「恢复队列」，才允许待发送消息继续执行。
- 已预约派发、但尚未确认会话保存的消息单独显示为「状态不确定」。普通恢复不会重放这些消息；先检查任务历史和实际文件，再选择「确认重试此消息」或「移除此恢复记录」。当前运行中的项目只显示等待保存确认，不允许再次重试。
- 队列先保存派发记录，再交给 worker；内存 `MessageEnd` 和回执不是磁盘提交。只有会话保存成功后才清理已接收项目。进程在两次保存之间退出时保留不确定状态，不能据此承诺外部模型或工具恰好执行一次。
- 队列保存原工作区；不同工作区不会直接消费旧的已展开输入。可以移回编辑，在当前工作区重新处理。队列按会话管理，不按会话树分支隔离，切换分支后也需要核对任务上下文。
- 读取失败、损坏或未来版本、锁冲突和写入失败会停止派发，不降级为空的内存队列继续发送。保留原文件，通过「重试读取本地队列」重新核对；保存结果未确认时不自动重试写入。
- 队列读写和控制在专用工作线程执行；快照读取不等待磁盘写入锁。journal 使用独占进程锁、版本检查、同目录唯一临时文件、刷盘及原子发布。会话文件使用唯一临时文件、刷盘、原子发布和进程内同路径写入串行化；它与 journal 不是跨文件原子事务。
- 退出不把保留队列当作用户清空；「移回编辑」则明确将该项移出持久队列，编辑中的普通输入框不是持久队列的一部分。

## Rust 分层

```text
egui WorkbenchState (页面 / 查询 / 筛选 / 检查器)
  ├─ TaskPhase / TaskProjection / BranchSnapshot (纯内存只读投影)
  ├─ artifact-preview worker → artifacts::read_recorded_artifact (真实文件读取)
  ├─ task-management worker → TaskStore (有序置顶与归档状态，不保存消息副本)
  ├─ 当前会话与 SessionStore 记录 (唯一会话数据来源)
  └─ 现有 worker 命令 (恢复 / 运行 / 取消 / 模型配置)
       └─ agent-runtime → agent-core → 厂商适配器 / 原生工具
```

没有为了模仿 Electron 新建 HTTP 服务或第二份会话数据库。
投影按 `(toolCallId, toolName)` 关联调用和结果，交错结果可正确匹配；重复/孤立/歧义结果不会编造文件产物。
搜索不扫描消息正文、凭据文件或真实磁盘。
产物与执行界面最多显示最近 100 条，diff 预览最多 24,000 个 Unicode 字符，完整内容仍在原有会话树/导出中。
详情缓存不保留原始工具参数、完整输出或图像负载。旧 JSONL 消息复用已有导入解码器；未知消息明确显示未纳入统计的数量。
文件预览只有一个工作线程槽位；取消后等待线程收尾才接受下一次读取，不在 UI 线程等待阻塞式 join。会话、分支、工作区或历史版本变化会丢弃旧响应；离开任务详情和释放应用状态时取消读取。文件正文不写回会话，也不进入 Debug 或错误字符串。
